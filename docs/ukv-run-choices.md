# UKV latest and previous completed run

UKV is one operational model. UK maps and Forecast Briefing expose two run choices: **UKV · latest** and **UKV · previous completed**, each with its initialization date and UTC cycle. There is no hourly-nowcast menu entry. Only 00/03/06/09/12/15/18/21Z initializations are eligible, while all hourly forecast valid steps within each run remain available. Location charts and their multi-model averages are unchanged.

The latest choice follows the newest published main initialization, including an incomplete run. The previous choice is exactly the newest earlier main run with explicitly verified `completed: true` metadata. An incomplete cycle, missing metadata or a missing completion flag cannot qualify based on horizon alone. When 03Z arrives, completed 00Z remains selectable. Completing 03Z does not remove 00Z; when 06Z arrives, completed 03Z replaces 00Z. If 03Z never completed, 00Z stays as the fallback until a more recent completed main run can be verified.

A shared map-run loader retains the current run and one completed predecessor in memory across the map views. On a fresh page, it discovers the predecessor from exact-cycle provider archive metadata, looking back at most 48 hours at three-hour intervals and stopping at the first verified completion. Forecast grids are loaded lazily from that cycle's own archive URLs; no full archive download is performed. Availability still depends on the provider retaining its published files. A 404 or incomplete run allows checking the next earlier main cycle; a server, network or identity error retains only an already verified fallback and reports the failed check. If no fallback can be verified, its menu choice is disabled rather than substituting an incomplete run.

Existing minute checks, hidden-tab behavior, UTC labels and the selected forecast valid time are preserved. Stale and out-of-order responses cannot roll either choice backwards or regress a completed run. The previous-choice role remains selected when it rolls forward. Each run keeps its own variables, supplied horizon, source URLs, cached imagery and accumulation intervals; the previous run never supplies imagery for the latest run or fills its missing fields/hours.

Normal UK maps comparing latest and previous UKV use every valid time available in either selected layer, so the completed run remains usable to its full horizon while the latest arrives. At a time unavailable in one panel, that panel hides all weather and overlays and explains the missing forecast; the other continues normally, including playback. Returning to a common time restores both maps. Loaded/total counts include only published frames. New hours refresh the panel even when the overall slider range is unchanged. Other model comparisons retain common valid times.

UKV Previous Run Analysis independently discovers three main runs: the current run and the two newest earlier completed runs, within the same 48-hour archive limit. The main map and Forecast Sequence dropdowns still expose only latest and previous completed. History keeps three panels, with shared valid times and rainfall periods available independently in all three runs. It automatically refreshes when the latest run or its coverage changes, and retries unsuccessful archive checks while retaining verified runs. Other models keep their original three-panel archive search and pinned comparison behavior.

Validation: `node --test tests/*.test.mjs`, the ensemble Python unit suite, and all browser scripts in `.github/workflows/map-browser-tests.yml`. `tests/ukv-retention-browser.mjs` exercises desktop/mobile maps, Briefing, history, completion, failed checks, reload discovery, rollover, UTC labeling in a non-UTC browser, native hourly steps and exact-cycle field URLs. Synthetic browser transport verifies application behavior, not provider throughput.
