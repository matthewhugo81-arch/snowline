# Separate UKV map choices

The map model menu offers **UKV — latest main run** (default) and **UKV — latest hourly nowcast**. Both use the same UKV 2 km source grid but have independent initialization selection. Main cycles are 0000/0300/0600/0900/1200/1500/1800/2100Z; intervening hourly initializations are the nowcast family. Within each group, the newest cycle with published forecast hours wins, including a run still arriving. Selection never depends on the furthest forecast endpoint. Thus an arriving 0600Z run replaces an older 0300Z 120-hour run immediately. No cycles or forecast fields are spliced together.

Selection starts at the newer of the provider's in-progress.json and latest.json, searches backwards at most 24 hours within the selected family and verifies each requested cycle's metadata. Only 404 (not yet published) or a cycle with no published hours allows trying an earlier cycle in that same group, with a visible explanation. A partial run with usable hours is accepted. Network, server and invalid-metadata errors during family selection stop selection rather than silently claiming an older cycle is newest. Shared metadata requests are deduplicated within each refresh; caches are revalidated every minute while the map or Briefing is visible. Failed refreshes retain the displayed forecast with an explicit retry message. Each map retains its own initialization/date and available endpoint. Comparison only offers common valid times, so switch comparison off for the full main-run horizon.

These are map-only options. The location-chart UKV model remains a single forecast entry, so multi-model means are not double-counted. The API identifier remains `ukmo_uk_deterministic_2km`; the map-only `_nowcast` choice is resolved to that domain before constructing data URLs. The earlier cutoff diagnostic is a historical snapshot predating these separate choices.

Run schedule: https://registry.opendata.aws/met-office-uk-deterministic/ (Met Office-managed catalogue). Feed identity: https://open-meteo.com/en/docs/ukmo-api. Supplied forecast coverage is read from each cycle's metadata; scheduled run length is not a promise of downloaded data.
